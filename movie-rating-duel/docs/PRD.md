## 1. 背景与问题

影迷在选片时面临三个具体摩擦：

1. **绝对评分不可比**：「8 分」对每个人的含义不同，跨时间也会漂移。
2. **给分成本高**：打开影评网站、找到条目、想一个数字，摩擦远大于「这部比那部好吗」的直觉判断。
3. **片单是扁平的**：收藏夹只有「想看」，没有「我更喜欢哪个」的排序，导致下一次选片依然靠猜。

而已有的「两两比较」工具多面向图片或论文，缺少电影响应、片库种子和分享形态。

## 2. 产品目标

> 用最低的交互成本（单次二选一），把用户脑中模糊的观影偏好，逐步压缩成一份可解释、可比较、可分享的个人电影排行榜。

**非目标**：不做影片播放、不做影评社区、不抓取第三方评分作为权威结论。

### 目标用户

| 画像 | 痛点 | 使用场景 |
| --- | --- | --- |
| 选择困难的普通观众 | 片单太长，不知道先看哪部 | 睡前 5 分钟做十几道对决 |
| 重度影迷 | 想有一份属于自己的百大片单 | 长期积累，年度回顾 |
| 小圈子好友 | 想知道彼此口味差多少 | 分享榜单、对比 |

## 3. 核心概念

- **Duel（对决）**：同时呈现 A、B 两部电影，用户的动作是「更想看 / 更喜欢」，可附加「平局」或「都没看过」。
- **Rating（分值）**：每用户对每部电影一个 Elo 分值，初始 `1000`，有效下限 `100`。
- **Leaderboard（榜单）**：按分值降序排列的该用户个人榜单。
- **Coverage（覆盖度）**：已参战电影数 / 片库总数，用于提示「你的榜单可信度」。

## 4. 用户故事与验收标准

### US-1 冷启动建立榜单（P0）

> 作为新用户，我可以连续做对决，系统逐步建立我的榜单。

**验收**：
- 首屏直接出现一对电影，无需注册、无需导入。
- 每完成一题自动出下一题，无强制弹窗。
- 完成 20 题后，榜单至少包含 12 部电影且排序稳定（连续两题不会让同一部电影在榜首和榜尾之间跳变）。

### US-2 分值变化可见（P0）

> 作为用户，我能看到刚才那道题把两部电影的分值改成了什么。

**验收**：
- 选择后以微动画展示 `±Δ`，1.5s 后自动进入下一题。
- Δ 与实际算法输出一致（允许四舍五入到整数）。

### US-3 否定选项（P1）

> 作为用户，我可以标记「都没看过」，且这次不计分。

**验收**：
- 该对决不改变任何分值。
- 同一对电影在用户片库内不再优先出现。

### US-4 撤销（P1）

> 作为用户，我可以撤销上一题。

**验收**：
- 撤销把双方分值恢复到该题之前的状态（需要保留前一分值快照）。
- 仅支持撤销一步。

### US-5 榜单分享（P1）

> 作为用户，我可以把 Top 10 导出成图片或链接。

**验收**：
- 生成的卡片包含标题、名次、电影名、年份、分值。
- 不包含任何个人身份信息。

## 5. 功能需求优先级

| 优先级 | 功能 | 说明 | 状态 |

| P0 | 对决卡片 | 双列海报 + 片名 + 年份 | 未开始（无界面） |
| P0 | 二选一交互 | 点击/滑动，键盘 ← → 可用 | 未开始 |
| P0 | Elo 更新 | 纯函数 `updateRatings` | **已实现** |
| P0 | 榜单 | 按分值降序，显示 Δ | **已实现**（CLI 模拟） |
| P0 | 本地持久化 | `localStorage` 单文件 JSON | 未开始 |

| P1 | 片库导入 | CSV / 手动添加 | 未开始 |

| P2 | Glicko-2 | 带置信区间 | 未开始（见 ADR-004） |

## 6. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏可交互 < 1s；单次对决到分值更新 < 100ms |
| 离线 | 纯前端可运行，无网络依赖（P0 阶段） |
| 存储 | 单用户数据 < 200KB |
| 隐私 | 无第三方追踪脚本；数据默认只存本地 |
| 兼容 | 移动端优先，宽度 320–1440px 自适应；支持键盘操作 |
| 可访问性 | 对比度 ≥ 4.5:1；对决结果不只用颜色区分 |

## 7. 成功指标

| 指标 | 目标 | 衡量方式 |
| --- | --- | --- |
| 首次会话完成对决数 | 中位数 ≥ 20 | 本地埋点（可选，需用户同意） |
| 对决平均决策时长 | 2–6 秒 | 同上 |
| 榜单回访（D7） | ≥ 25% | 同上 |
| 测试覆盖（核心逻辑） | 行覆盖 ≥ 90% | `node --test --experimental-test-coverage` |

## 8. 范围外（本项目不考虑）

- 账号体系、登录、跨设备同步（P0–P1）
- 影片版权播放、预告片托管
- 抓取豆瓣 / IMDb 评分做「客观分」对比
- 社交关注、评论、弹幕

## 9. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 冷启动片库太小 | 反复出现同几部电影，对决无信息量 | 种子片库 ≥ 60 部，按题材分层抽样 |
| 「都没看过」被滥用 | 榜单稀疏 | 记录跳过次数，同一对最多跳过 1 次 |
| Elo 收敛慢 | 新电影分值长期不可信 | 每部电影前 5 场使用更高 K 值（见开放问题 Q1） |
| 用户口味随时间变化 | 分值陈旧 | P2 引入时间衰减权重 |

## 10. 开放问题

- **Q1**：K 值是否按参赛场次自适应（新手 40 → 收敛后 16）？需要模拟对比收敛速度。
- **Q2**：平局是否固定 0.5 分，还是按实力差做部分得分？
- **Q3**：榜单是否需要显示置信区间（场次少的电影标注「数据不足」）？
- **Q4**：片库来源是内置种子、用户手动导入，还是两者都要？
