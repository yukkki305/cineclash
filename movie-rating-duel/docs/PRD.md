# PRD — 谁的评分更高？（Movie Rating Duel）

> 状态：**v0.2 已实现**（MVP 可玩，单元/组件测试通过）。
> 规则编号与仓库根 `AGENTS.md` 的 15 条游戏规则一一对应。

## 1. 产品定位

一个纯浏览器端的「电影评分二选一」小游戏：屏幕同时给出两部电影，玩家点出**评分更高的那一部**。
答对得分，答错扣命，5 条命用完游戏结束。核心乐趣是「我以为这部更高」的认知暴击，
而不是考据影史，所以题目的**评分差被难度严格控制**。

## 2. 目标用户

- 想用碎片时间玩 1–3 分钟、不需要注册和学习的休闲玩家。
- 对电影有基本熟悉度、愿意被自己的直觉打脸的影迷。
- 不需要任何账号体系，打开即玩。

## 3. 核心循环

```
首页（选难度 + 年份范围 + 看配对数）
  → 开始 → 出一道题（两部电影、片名 + 年份、评分隐藏）
  → 玩家点击其中一部
  → 立即反馈：对/错、双方真实评分与来源、正确答案高亮
  → 下一题（配对历史累加，不重复）
  → 生命归零 / 无合法题目 → 结束页（得分、已作答、答对、正确率、剩余生命）
  → 再来一局（沿用上次配置，全部数值重置）或回首页
```

## 4. 游戏规则（对应 AGENTS.md 规则 1–15）

| # | 规则 | 实现位置 |
| --- | --- | --- |
| 1 | 新局恰好 5 条命 | `src/game/engine.ts` `LIVES_PER_GAME` |
| 2 | 答对 +1 分（不加命） | `answerQuestion` |
| 3 | 答错恰好 −1 条命 | `answerQuestion` |
| 4 | 生命不低于 0 | `answerQuestion` 中 `Math.max(0, ...)` |
| 5 | 每题只作答一次 | `answerQuestion` 检测 `state.feedback` |
| 6 | 结束后不再接受作答 | `answerQuestion` 检测 `phase !== 'playing'` |
| 7 | 生命归零立即进入结束页 | `answerQuestion` 中 `phase: lives === 0 ? 'finished'` |
| 8 | 重开重置得分/生命/计数/配对历史 | `startGame` / `restartGame` |
| 9 | 同一题的两部电影 ID 必须不同 | `isLegalPair` 首行 |
| 10 | 评分相同的两部不得作为普通题 | `isLegalPair` 中 `gap <= 0` 排除 |
| 11 | 两部电影都要落在年份范围内 | `isInYearRange`（对 a、b 双向校验） |
| 12 | 评分按数值比较，不做字符串比较 | `hasComparableRating` + 数值 `ratingGap` |
| 13 | 无合法配对时安全终止，绝不进入死循环 | `selectQuestion` 返回 `null` → `exhausted` |
| 14 | 左右位置不得系统性偏向高分电影 | `selectQuestion` 中 `swap` 由随机源决定 |
| 15 | 本局内只要有未用合法配对，就不得重复同一无序配对 | `usedPairs` + `pairKey`（小 ID 在前） |

正确率：`答对 / 已作答`；未作答时**不显示 0%**，显示「暂不可用」（见 `accuracyOf` 返回 `null`）。

## 5. 难度

`src/game/difficulty.ts` 是唯一数据源，UI 不得重复定义阈值。

| 难度 | 评分差绝对值区间 | 设计意图 |
| --- | --- | --- |
| 普通 Normal | 0.8 – 2.0 | 靠印象就能答对，用来上手 |
| 进阶 Advanced | 0.3 – 0.7 | 需要一点印象比对 |
| 专家 Expert | 0.1 – 0.2 | 纯直觉赌博 |

阈值是可调参数；调参只改这一个文件，测试会跟随 `DIFFICULTIES` 读取。

## 6. 数据政策（硬约束）

- 当前片库为 **60 条合成测试数据**（`src/data/movies.ts`，ID `m001`–`m060`，年份 2005–2025，
  评分 3.1–9.9 且互不相同，片名全部虚构）。
- 每条记录都带 `ratingSource`，统一为「合成测试数据（非真实评分）」，并在 UI 中显示免责声明。
- **绝不允许**把合成评分说成豆瓣评分；接入真实数据必须另起任务并获得批准。
- 所有数据进入游戏前必须经过 `src/data/validate.ts`：重复 ID、重复记录、空标题、非法年份、
  非有限或越界评分、缺失评分来源、非法海报 URL 都会被拦下并如实报告。

## 7. MVP 范围

已包含：首页说明与免责声明、3 档难度、起始/结束年份筛选、双片对比题、片名 + 年份、
作答后展示评分与来源、5 条命、单次提交、对错反馈、每题 +1 分、答错 −1 命、
结束页（得分 / 已作答 / 答对 / 正确率 / 剩余生命）、再来一局、响应式布局、
缺图降级、题目不足时的优雅终止。

明确不做（本阶段）：注册登录、全球排行榜、多人对战、付费、社交分享、AI 生成评分、
自适应难度、仅为单人逻辑搭后端。

## 8. 关键界面与文案

- 首页：难度选择、年份输入、`片库覆盖 2005–2025 年`、合法配对数、开始按钮。
  输入非法时按钮禁用，并给出**唯一**一条最相关的错误提示：
  年份非 4 位数字 → 超出片库范围 → 起始晚于结束 → 该条件下没有合法题目。
- 游戏中：`第 N 题`、`剩余生命 N / 5`、得分、正确率；作答前评分显示为「评分已隐藏」。
- 结束页：区分「生命耗尽，本局结束。」与「当前筛选下的题目已用尽，本局提前结束。」两种结局。

## 9. 验收标准

1. `pnpm test` 全绿，覆盖全部 15 条规则的关键路径。
2. `pnpm run typecheck` 与 `pnpm run build` 无错误。
3. 任一难度 + 任一年份区间下，不会因为「抽不到题」而卡死或白屏。
4. 结束时所有统计数字与作答历史一致；重开后全部归零。

## 10. 已知风险与后续规划

| 风险 | 现状 | 计划 |
| --- | --- | --- |
| Expert 区间（0.1–0.2）在 60 部片库下可出题数很少 | 首页会显示配对数并提前拦截 | 扩充片库（用户已确认后期处理） |
| 规则 15 + 年份筛选收窄时配对会很快耗尽 | 耗尽后允许复用配对继续玩，绝不卡死 | 同上，扩充片库 |
| 只有合成数据，不具备「真实观影认知」乐趣 | 明确标注为测试数据 | 单独任务评估合法数据源 |
| 尚无真实浏览器以外的自动化 | 单元 + 组件测试，另有 4 条 Playwright 冒烟 | 补充难度/终局的 E2E 用例 |
